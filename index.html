Distributed Rate Limiter

Backend systems · Redis
Problem
In-process rate limiting fails in horizontally scaled deployments because every instance holds its own state. Limits must be enforced consistently across stateless service replicas.
Solution
Designed a Redis-backed rate limiting service that implements five algorithms (token bucket, leaky bucket, fixed window, sliding window log and sliding window counter) behind a common interface. Each check-and-update runs atomically as a Lua script. The service is deployed as two stateless FastAPI replicas behind an nginx load balancer, with per-tier quotas, standard rate-limit response headers, Prometheus metrics and an interactive dashboard that compares the algorithms.
Outcome
Under 50 concurrent requests against a limit of 5, the fixed-window and both sliding-window implementations admitted exactly 5. A load test on a single instance sustained about 330 requests per second at 22 ms p99 latency with zero errors. 22 automated tests verify the behaviour, and a CI pipeline runs linting, tests and Docker builds on every push.

Blood Donor Finder

Full-stack · .NET and React
Problem
Urgent blood requests are coordinated through informal channels, and many responders are incompatible, ineligible or too far away, which delays care.
Solution
Engineered a full-stack platform (ASP.NET Core 8 API, React front end) that filters donors before contact using blood-group compatibility rules, a 90-day donation eligibility window, and distance ranking with the Haversine formula. It also provides an emergency requests board with urgency tiers, SMS alerting through Twilio, JWT authentication with salted PBKDF2 password hashing, rate limiting on search and authentication endpoints, masked contact data for anonymous users, and a dashboard that flags supply shortages.
Outcome
Delivered with 33 passing xUnit unit and integration tests, OpenAPI (Swagger) documentation, and seeded demo data for a two-command local setup.

Resume Tailor and ATS Checker

LLM application · Live demo
Problem
Job applicants must adapt a resume to every posting by hand, with little insight into how an applicant tracking system will evaluate it.
Solution
Developed and deployed a web application that sends a resume and job description to an LLM through a Node.js and Express API. It returns an ATS match score, matched and missing keywords, role-aligned bullet rewrites and formatting guidance as structured JSON. The API key is held server-side, and prompts constrain the model to facts present in the resume.
Outcome
Running in production on Render with per-IP rate limiting (10 requests per 10 minutes), input size limits and request body caps. The demo runs on a free tier, so the first load can take about a minute.

Spam and Fake News Detector

ETL and ML pipeline · Built during my AI/ML internship
Problem
Text classification models are difficult to trust unless every pipeline stage is tested and candidate models are evaluated under identical conditions.
Solution
Implemented an end-to-end NLP training pipeline with configurable preprocessing, word and character n-gram TF-IDF features, nine engineered features, five Scikit-learn classifiers and three TensorFlow and Keras architectures (TextCNN, BiLSTM and CNN-LSTM). Evaluation uses stratified cross-validation and per-model threshold optimisation for F1, and reports precision, recall, F1, ROC-AUC and inference latency.
Outcome
Covered by 50 pytest unit and integration tests. The pipeline currently trains on a synthetic dataset generated by the project, so the reported scores validate the pipeline rather than real-world accuracy.
